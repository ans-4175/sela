# Bounded Gmail bulk Trash

User approved offline implementation of explicitly reviewed batches, up to 100 messages each. User selected Inbox messages in five UI categories plus all Spam; starred, important and drafts are protected. SENT and TRASH are also protected. Approval of the design is not permission to access or change Gmail, install or release this version.

A batch preview accepts 1–100 unique explicit message IDs, one source (`inbox` or `spam`), and for Inbox exactly one supported category label. Read-only, explicit paginated Gmail search supplies candidate IDs; no query-to-write expansion, no automatic pagination, no thread operations. Search's explicit `--include-spam` passes Gmail's includeSpamTrash option, so it includes Trash in read results too. The later eligibility check excludes it. Preview produces a full fixed list of eligible message snapshots and per-ID skipped reasons; any read failure aborts preview. Verify chosen system category labels; the Gmail Purchases UI may not expose `CATEGORY_PURCHASES` in the API, and this implementation never infers membership from a query alone. Missing category label means skipped.

Each batch has its own hash-bound exact approval and fifteen-minute expiry. Gmail modify scope consent is independent. `plan execute` durably claims the batch and persists each item as `in_flight` before fresh metadata/eligibility verification, one native message Trash write, and label readback; only then does it persist `verified_trashed`. Errors stop immediately with `unknown`, leaving later items `not_attempted`; cancellation/expiry before an item sets the plan `partial`. A process crash may leave the last item `in_flight` and plan `executing`. A claimed batch cannot resume or replay; `plan show` supplies durable per-message evidence for separate reconciliation. New plans for remaining work require fresh preview and actual user approval. Global plan lock serializes local executions. It does not protect against other Gmail clients or create distributed exactly-once behavior. Gmail does not provide an atomic check-and-trash here; state can change after the fresh check.

Offline tests use synthetic data and mocks only. No claim of live Spam-to-Trash behavior, Gmail category membership, or large-account pagination completeness. Trash can later be permanently deleted by Gmail retention or account policy; permanent delete, auto-restore, background processing and unlimited bulk are not exposed.
