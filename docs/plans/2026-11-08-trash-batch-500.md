# Raise Trash batch cap to 500 (offline candidate)

User approved raising the cap for implementation only, not installation, release, Gmail access or writes. Exact snapshots, one explicit approval per batch, protected labels, one native message request per item, durable per-item claims/results, stop-on-unknown and no replay remain unchanged. Existing plans of up to 100 are not reinterpreted. Search remains explicitly paginated up to 100 per call; it never expands the approved IDs automatically.

The limit is a maximum, not a promise of 500 completed items. Preview is capped at ten minutes for all 500 sequential bounded metadata reads; failure, cancellation or timeout yields no plan. Existing plan lifetime remains 15 minutes from plan creation and includes human review. Execute stops before the next item on expiration/cancellation; an in-flight Gmail request also has the plan expiry as a context deadline. A timed-out/cancelled in-flight item is unknown, while a crash/interrupt may leave it in_flight; never resume or retry the plan automatically. Check `plan show` and reconcile unknown items before any new separately approved plan. At 500, 500 preflight reads, up to 500 writes, 500 readbacks and more than 1,000 durable local writes may take substantial time and hit quota/rate limits. No unapproved parallelization or bulk provider request was introduced. The expiry is not extended to avoid silently widening authorization.

`--ids` remains one command argument: up to 500 IDs of 128 bytes plus commas (64,499 bytes), visible in process arguments and potentially shell history; treat IDs and plan data as private, do not publish logs or paste into tracked files. OS execution argument limits vary; if invocation fails use smaller exact batches. This change does not introduce a file input, extra copies of IDs or imply a privacy guarantee against same-user processes.

No live 500-message throughput, Spam Trash behavior, category mapping, production quota or timing has been established. Offline tests use synthetic data; no new user data or credentials.
